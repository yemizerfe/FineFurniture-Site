Personal Blog API · v1.0.0

CRUD for one blogger's articles.

A small JSON REST API backed by SQLite. Create drafts, publish posts, tag them, search them, and read them back with pagination — all over plain HTTP.

checking… base URL CORS enabled

Quick start

Every response is JSON wrapped in data, with error for failures.

# list published articles
curl "/api/articles?status=published&limit=5"

# create a draft
curl -X POST "/api/articles" \
  -H "content-type: application/json" \
  -d '{
    "title": "Notes on Edge Functions",
    "content": "Cold starts, CPU budgets, and isolates.",
    "tags": ["edge", "workers"],
    "status": "draft"
  }'
# publish it (partial update by slug)
curl -X PATCH "/api/articles/notes-on-edge-functions" \
  -H "content-type: application/json" \
  -d '{"status": "published"}'

# search, then delete
curl "/api/articles?q=isolates"
curl -X DELETE "/api/articles/42"

Endpoints

Look articles up by numeric id or by slug — both work anywhere :idOrSlug appears.

MethodRouteWhat it does
GET/api/articlesList articles. Filters: status, tag, q; paging: limit (≤50), offset; sort: newest|oldest|title|updated.
POST/api/articlesCreate an article. Requires title and content. Returns 201 with a Location header.
GET/api/articles/:idOrSlugFetch one article, including its full content.
PATCH/api/articles/:idOrSlugPartially update: only the fields you send change. Publishing sets published_at once.
PUT/api/articles/:idOrSlugReplace the editable fields; title and content are required.
DELETE/api/articles/:idOrSlugDelete an article permanently.
GET/api/tagsAll tags in use, with article counts.
GET/api/bloggerThe blogger's profile (name, bio, links).
PUT/api/bloggerUpdate the profile fields you send.
GET/api/healthLiveness probe plus article count.

Article shape

  • id — integer primary key
  • title — required, ≤ 200 chars
  • slug — unique, generated from the title unless you send one
  • excerpt — auto-derived from content when omitted
  • content — required on create, plain text or markdown
  • tags — array of up to 10 lowercase strings
  • status — draft or published
  • cover_image — optional URL
  • published_at — ISO 8601, set when first published
  • reading_minutes, word_count — computed on read
// GET /api/articles/hello-world-again
{
  "data": {
    "id": 1,
    "title": "Hello, World (Again)",
    "slug": "hello-world-again",
    "excerpt": "Why I am starting yet another blog…",
    "tags": ["meta", "writing"],
    "status": "published",
    "cover_image": null,
    "reading_minutes": 1,
    "published_at": "2026-01-12T09:00:00.000Z",
    "url": "/api/articles/hello-world-again",
    "content": "Every few years I wipe the archive…"
  }
}

Errors

Failures return a matching HTTP status and a machine-readable code: bad_request, not_found, conflict, method_not_allowed, unsupported_media_type, payload_too_large. 

{
  "error": {
    "code": "bad_request",
    "message": "\"title\" must be at most 200 characters.",
    "details": { "field": "title" }
  }
}
